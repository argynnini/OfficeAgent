# エージェントの状態 - Win32 apps | Microsoft Learn

[Microsoft エージェントは Windows 7 の時点で非推奨となり、以降のバージョンの Windows では使用できない場合があります。]

Microsoft Agent アニメーション サービスは、特定のアニメーションを自動的に再生します。 たとえば、 [**MoveTo**](moveto-method) または [**GestureAt**](gestureat-method) コマンドを使用すると、アニメーション サービスによって適切なアニメーションが再生されます。 同様に、アイドルタイムアウト後、サービスは自動的にアニメーションを再生します。 これらの状態をサポートするために、適切なアニメーションを定義し、それらを状態に割り当てることができます。 Play [**メソッドを**](play-method) 使用して直接定義したアニメーションは、状態に割り当てても再生できます。

複数のアニメーションを同じ状態に割り当てることができ、アニメーション サービスはアニメーションの 1 つをランダムに選択します。 これにより、あなたのキャラクターは、その動作にはるかに自然な多様性を示すことができます。

状態に割り当てるアニメーションには分岐フレームを含めることができますが、ループ アニメーション (永遠に分岐するアニメーション) は避けてください。 それ以外の場合は、別のアニメーションを再生する前に [**Stop**](play-method) メソッドを使用する必要があります。

文字に対して発生する状態ごとに少なくとも 1 つのアニメーションを定義して割り当てることが重要です。 これらのアニメーションと状態の割り当てを指定しないと、キャラクターがユーザーに対して適切に動作していないように見える可能性があります。 ただし、特定の文字に対して状態が発生しない場合は、その状態にアニメーションを割り当てる必要はありません。 たとえば、ホスト アプリケーションが [**MoveTo**](moveto-method) メソッドを呼び出さない場合は、 **移動** 状態アニメーションの作成と割り当てをスキップできます。

### 聴覚とリスニングの状態

ユーザーが音声入力用のプッシュツートーク ホット キーを押すと、 **リッスン** 状態に割り当てるアニメーションが再生されます。 キャラクターを注意深く見せる短いアニメーションを作成して割り当てます。 同様に、短い期間になるように **Return** アニメーションを定義して、ユーザーが話すときにキャラクタが **ヒアリング** 状態アニメーションを再生できるようにします。 **ヒアリング**状態のアニメーションも短くし、キャラクターがユーザーの言うことを積極的に聞いていることをユーザーに知らせるために設計されている必要があります。 頭の傾きやその他のわずかなジェスチャが適切です。 自然な変動性を提供するには、 **いくつかの聴覚** 状態アニメーションを提供します。

### ゲスリング状態

ジェスチャ **状態アニメーション** を作成して割り当てる必要があるのは、 [**GestureAt**](gestureat-method) メソッドを使用する場合のみです。 ジェスチャ**状態アニメーション**は、Microsoft エージェントが **GestureAt** メソッドの呼び出しを処理するときに再生されます。 **Gesturing** 状態アニメーションのマウス オーバーレイを定義すると、キャラクターはジェスチャとして話すことができます。

アニメーション サービスは、文字の位置と、 メソッドで指定された座標の位置との関係を決定し、適切なアニメーションを再生します。 ゲストリングの方向は、常にキャラクターに関してです。たとえば、 **GestureRight** は文字の右へのジェスチャである必要があります。

### 表示と非表示の状態

[ **表示** ] と **[非表示]** の状態は、ユーザーまたはホスト アプリケーションが文字の表示/非表示を要求したときに、割り当てられたアニメーションを再生します。 これらの状態では、文字フレームの Visible 状態も適切に設定 **されます** 。 これらの状態のアニメーションを定義する場合は、任意の画面の場所で文字を表示または退出できることに注意してください。 ユーザーは任意の文字を表示または非表示にできるため、常にこれらの状態に対して少なくとも 1 つのアニメーションをサポートします。

**[表示**中] 状態に割り当てるアニメーションは、通常、キャラクターのニュートラルな位置イメージを含むフレームで終わります。 逆 **に、非表示** 状態のアニメーションは通常、ニュートラルな位置から始まります。 状態アニメーションの**表示**と**非表示**には、文字の現在の状態からの遷移を提供するために、それぞれ先頭または末尾に空のフレームを含めることができます。

### アイドリングの状態

**アイドリング**状態はプログレッシブです。 アニメーション サービスは、最初のアイドル期間にレベル 1 の割り当ての使用を開始し、第 2 レベルのアニメーションを使用します。 その後、アイドル サイクルはレベル 3 に割り当てられたアニメーションに進み、新しいアニメーション要求が開始されたときなど、キャンセルされるまでこの状態のままになります。

**Idling** 状態のアニメーションをデザインして、キャラクターの状態を伝えますが、ユーザーの注意をそらすものではありません。 アニメーションは、微妙だが明確な方法でキャラクターの応答性を適切に反映する必要があります。 たとえば、周りを見回したり点滅したりすると、 **IdlingLevel1** 状態に割り当てるのに適したアニメーションになります。 アニメーションの読み取りは **、IdlingLevel2** 状態に対して適切に機能します。 睡眠やヘッドフォンで音楽を聴くのは、 **IdlingLevel3** 状態に割り当てるアニメーションの良い例です。 多くの動きや大きな動きを含むアニメーションは、ユーザーの注意を引くので、アイドル状態のアニメーションには適していません。 **Idling** 状態アニメーションは頻繁に再生されるため、特に **IdlingLevel1 と IdlingLevel2** の状態に対して、いくつかの Idling 状態アニメーション**を**提供します。

アプリケーションは、文字の自動アイドル処理をオフにし、文字の **アイドリング** 状態自体を管理できることに注意してください。 エージェント **アイドリング** の状態は、キャラクターに再生するアニメーションがない状況を回避するために設計されています。 しばらくすると変わらない文字画像は、アプリケーションが長時間待機ポインターを表示し、信じやすさと対話性の感覚を損なうようなものです。 錯覚の維持には、アニメーション化された点滅、目に見える呼吸、または体のシフトだけが必要な場合があります。

### 話す状態

現在のアニメーションで **読み上げ** アニメーションが見つからない場合、アニメーション サービスは読み上げ状態を使用します。 この状態に単純な読み上げアニメーションを割り当てます。 たとえば、マウス オーバーレイを使用して、キャラクターのニュートラルな位置で構成される 1 つのフレームを使用できます。

### 移動状態

アプリケーションが [**MoveTo**](moveto-method) メソッドを呼び出すと、**移動**状態が再生されます。 アニメーション サービスは、キャラクターの現在の位置と指定した座標に基づいて、再生するアニメーションを決定します。 移動方向は、キャラクターの位置に基づいています。 したがって、 **MovingLeft** アニメーションに割り当てるアニメーションは、キャラクタの左側に基づく必要があります。 **MoveTo** メソッドを使用しない場合は、アニメーションの作成と割り当てをスキップできます。

**移動** 状態のアニメーションは、キャラクターを移動位置にアニメーション化する必要があります。 このアニメーションの最後のフレームは、キャラクターのフレームが画面に移動すると表示されます。 フレームの移動中にキャラクターをアニメーション化することはできません。

### 標準アニメーション セット

使用するアニメーションを持つカスタム文字を設計できますが、Microsoft Agent では標準のアニメーション セットが定義されています。 この定義に準拠する文字は、既定の文字として選択できます。

次の表に、標準のアニメーション セットに含まれるアニメーションの一覧を示します。 カスタム文字を作成する場合でも、独自の文字を設計するためのガイドとしてリストを使用できます。 標準アニメーション セットをサポートする文字は、少なくとも次のアニメーションをサポートする必要があります。

| **アラート**^1,2^ | 文字が指示を待っているとき、通常はユーザーがリスニング モードをオンにした後に再生されます。 | キャラクターは正面に向かい、呼吸し、時々点滅しますが、明らかに指示を待っています。 |

| **読み取り中** | 文字が何かを読み取るが、入力を受け入れることができない場合。 | 紙から文字を読み取ります。 注: このアニメーションは、キャラクタが適切な位置に移動した後に発生する中間フレームにループします。 |
| **RestPose** | 文字が中立的な位置から話す場合。 | キャラクターはリラックスしたが、注意深い姿勢で立っています。 |
| **Sad**^1,2^ | ユーザーの選択に文字ががっかりした場合。 | 文字が見えなかったり、がっかりしているように見えます。 |
| **Search** | 文字が何かを検索するとき。 | 何かを探しているファイル ドロワーまたはその他のコンテナーを介して文字シャッフルします。 |
| **検索** | 文字がユーザー指定の情報を検索している場合。 | 何かを探しているファイル ドロワーまたはその他のコンテナーを介して文字シャッフルします。 注: このアニメーションは、キャラクタが適切な位置に移動した後に発生する中間フレームにループします。 |
| **表示** | キャラクターが起動したとき、または召喚された後に戻ったとき。 | キャラクターが煙、ビーム、または画面上を歩くパフでポップアップします。 |
| **StartListening**^1,2^ | 文字がリッスンしているとき。 | キャラクターは耳に手を置きます。 |
| **StopListening**^1,2^ | 文字がリッスンを停止したとき。 | キャラクターは耳の上に手を置きます。 |
| **提案**^1,2^ | 文字にユーザーのヒントまたは提案がある場合。 | 文字の横に電球が表示されます。 |
| **驚き**^1,2^ | ユーザーの操作または選択に文字が驚いた場合。 | キャラクターは目を広げ、口を開きます。 |
| **考える**^1,2^ | キャラクターが何かを考えているとき。 | キャラクターは上を見上げ、頭の上に手を握ります。 |
| **不確実**^1,2^ | ユーザーが要求を確認する必要がある場合。 | キャラクターはクイズのように見え、伝えます(「よろしいですか?) |
| **Wave**^1,2^ | ユーザーがサーバーまたはシステムをシャットダウンすることを選択した場合。 | キャラクターは、さよおややこんにちは波。 |
| **書き込み** | 文字がユーザーからの指示をリッスンしている場合。 | 文字は、紙を表示し、書き込み、ユーザーを振り返ります。 |
| **WriteContinued** | 文字がユーザーからの指示をリッスンし続けるとき。 | 文字は紙に書き込み、ユーザーを振り返ります。 |
| **WriteReturn** | 文字が Write アニメーションまたは **WriteContinued** アニメーションを完了したとき。 | 文字はニュートラルな位置に戻ります。 |
| **書き込み** | 文字がユーザーの情報を書き出す場合。 | 文字は紙に書き込まれます。 注: このアニメーションはループします。 |

アニメーションには、口のオーバーレイと定義された読み上げフレームが必要です。

アニメーションには、終了分岐または明示的な Return アニメーションに基づいて、Return アニメーションが割り当てられている必要があります。
